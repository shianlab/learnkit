# 给 AI 的开发指南

让 AI 先阅读 README.md、AGENTS.md、docs/ARCHITECTURE.md 和 docs/IMPORT.md，再处理文件。不要只把一个截图给 AI 然后让它重新写整个应用。

## 可直接复制的提示词

> 请基于这个 RikeDesk 本地学习框架制作我的课程学习应用。先读取项目说明和代码结构，保留持续播放、阅读、笔记、搜索、计划、复习与备份功能。我的课程资料位于【目录】，应用名称是【名称】，作者是【作者】。先扫描文件名，生成音频/文稿匹配报告；配对有冲突时列出候选供我确定，不要猜测。设置独立的 appId 和 libraryId。将 PDF/Word 文稿转换成 Markdown 前，先检查文本提取和图表是否完整。填入 courses.json，保持课程 ID 稳定。先运行少量示例，验证听读与笔记，再导入全部资料并打包。不要上传课程、密钥、个人笔记、node_modules 或构建产物。完成后告诉我已验证的功能和仍需实机验证的部分。

## 改造顺序

1. 用四门自制示例启动，确认开发环境与原功能可用。
2. 修改 app/app.config.json，设置独立应用身份。
3. 只读扫描自己的目录；核对同名冲突、缺文稿和纯文稿，明确映射。
4. 先导入小样本，验证实际格式、中文正文、音频、划线和恢复备份。
5. 导入全部资料；重建搜索索引；再调整名称、颜色、页面与课程分类。
6. 运行测试和构建，打包整个 Windows 运行文件夹，使用空白个人数据目录验证。

## 修改约束

不要把课程数、分组数、统计数字或某个默认课程 ID 写死。个人数据不放在课程目录里。添加导入功能时保留路径边界、冲突报告、文件校验、稳定 ID 与失败时保留旧库的行为。保留播放器在页面切换时的独立生命周期；在编辑未保存时不要强制切换或退出。

PDF/Word 转换、语音识别、自动摘要和云同步是可选扩展，不是现有能力。没有接入真实服务或未执行测试时，不要宣称已经完成。
